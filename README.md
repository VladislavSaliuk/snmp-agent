# SNMP Agent — Special Purpose Network Simulator

Дипломний проєкт: програмний **SNMP-агент**, що імітує мережеве обладнання спеціального призначення (маршрутизатори, комутатори, IED-контролери) і дозволяє відтворювати сценарії кіберінцидентів та радіоелектронної боротьби (РЕБ) для систем моніторингу на кшталт **Zabbix**.

Агент відповідає на стандартні SNMP `GET`/`GETNEXT` запити, надсилає `Trap`-сповіщення менеджеру та підтримує **Custom MIB** (Enterprise OID `1.3.6.1.4.1.99999`) для метрик, яких немає у типового обладнання Cisco/Juniper — зокрема рівня сигнал/шум (SNR) та статусу шифрування.

## Можливості

- **SNMP v2c агент** на основі `snmp4j` — пряма обробка PDU через `CommandResponder` (без `BaseAgent`).
- **MIB-реєстр** зі стандартними та кастомними OID (SNR, статус шифрування, температура).
- **Trap-сповіщення** до менеджера (Zabbix) при критичних подіях.
- **Три сценарії інцидентів**, що змінюють значення метрик у часі:
  1. **Lateral Movement** — горизонтальне переміщення атаки (сканування Modbus TCP, ріст `ifInErrors`, стрибок CPU).
  2. **РЕБ** — поступове придушення радіоканалу (падіння SNR `35 → 3 dB`).
  3. **Збій шифрування** — перехід на передачу у відкритому вигляді (`encryptionStatus = 0`).
- **HTTP API** для керування симуляцією ззовні (зокрема з-поза Docker).
- **Локальне інтерактивне меню** для ручного запуску сценаріїв.
- **SnmpTester** — вбудований клієнт для перевірки відповідей агента.
- **Docker-середовище** з Zabbix та чотирма агентами (router, switch, server, IED).

## Структура

```
src/main/java/
  Main.java              — точка входу, вибір режиму (Docker / локальний)
  SnmpAgent.java         — SNMP-агент, MIB-реєстр, simulation hooks
  TrapSender.java        — надсилання SNMPv2c Trap до менеджера
  SimulationEngine.java  — "режисер" сценаріїв (ScheduledExecutorService)
  SimulationApi.java     — HTTP API для запуску сценаріїв
  SnmpTester.java        — SNMP-клієнт для перевірки агента
src/test/java/           — JUnit-тести (Agent, Engine, Tester, TrapSender)
Dockerfile               — образ агента (eclipse-temurin:17-jre-alpine)
docker-compose.yml       — Zabbix + 4 агенти у мережі 192.168.100.0/24
```

```

```

## Запуск

### Локальний режим (інтерактивне меню)

Якщо змінна оточення `DEVICE_TYPE` **не** задана, агент слухає на `0.0.0.0/16100`, а Trap-и летять на `127.0.0.1/162`.

```bash
java -jar target/snmp-agent-1.0-SNAPSHOT.jar
# Або вказати адресу менеджера першим аргументом:
java -jar target/snmp-agent-1.0-SNAPSHOT.jar 192.168.0.50/162
```

Меню керування:

```
[1] Сценарій: Lateral Movement
[2] Сценарій: РЕБ (придушення сигналу)
[3] Сценарій: Збій шифрування
[R] Скинути стан до нормального
[M] Показати меню
[Q] Вийти
```

Перевірка агента вбудованим клієнтом (порт `16100`):

```bash
java -cp target/snmp-agent-1.0-SNAPSHOT.jar SnmpTester
```

Або стандартними утилітами:

```bash
snmpget -v2c -c public localhost:16100 1.3.6.1.4.1.99999.2.0   # SNR
```

### Docker-режим

Якщо задано `DEVICE_TYPE`, агент слухає на стандартному порту `0.0.0.0/161`, а Trap-и надсилаються на Zabbix-контейнер `192.168.100.10/162`. Інтерактивне меню вимкнено — процес тримається живим у фоні.

```bash
./mvnw clean package        # спочатку зібрати jar
docker compose up -d
```

Розгортається:

| Сервіс  | Пристрій         | IP               | HTTP API (host) |
|---------|------------------|------------------|-----------------|
| zabbix  | Zabbix appliance | `192.168.100.10` | `:80`, `:162/udp` |
| router  | CORE-ROUTER-01   | `192.168.100.2`  | `:8161`         |
| switch  | CORE-SWITCH-01   | `192.168.100.3`  | `:8162`         |
| server  | APP-SERVER-01    | `192.168.100.4`  | `:8163`         |
| ied     | IED-BREAKER-01   | `192.168.100.5`  | `:8164`         |

Веб-інтерфейс Zabbix: http://localhost (логін за замовчуванням `Admin` / `zabbix`).

## HTTP API керування симуляцією

Агент піднімає HTTP-сервер на порту **`8161`** для запуску сценаріїв без доступу до stdin (у Docker пробрасується на хост-порти `8161`–`8164` згідно з таблицею сервісів вище):

```bash
curl "http://localhost:8161/simulate?scenario=reb"
curl "http://localhost:8161/simulate?scenario=lateral"
curl "http://localhost:8161/simulate?scenario=encryption"
curl "http://localhost:8161/simulate?scenario=reset"
curl "http://localhost:8161/status"
```

## Сценарії

### 1. Lateral Movement (Modbus TCP Scan)
Імітація шкідливого ПЗ, що сканує мережу в пошуках IED-контролера. Зростає `ifInErrors` (+200), CPU стрибає до 88%, надсилаються Trap-и про втрату пакетів і перевантаження. Через 20 с стан автоматично відновлюється.

### 2. РЕБ (радіоелектронна боротьба)
SNR знижується на 8 dB кожні 2 секунди (`35 → 27 → 19 → 11 → 3 dB`). На 4-му кроці (SNR < 10 dB) надсилається критичний Trap. Кастомний OID SNR дозволяє відрізнити апаратний збій від навмисного придушення сигналу.

### 3. Збій шифрування
`encryptionStatus` стає `0` (відкрита передача), надсилається критичний Trap. Через 4 с імітується ротація ключів і відновлення.
